Capabilities

Two commands cover the two places secrets escape

Every capability below is implemented in the codebase and exercised by the test suite.

✓

.env linting — check

Compare a real .env against its .env.example. Catches missing keys, extra unexplained keys, duplicates, commented-out keys, quoting pitfalls, malformed lines and empty required values.

--strict--allow--require--json
🛰️

Repository secret scanning — scan

Walk the whole tree and flag likely leaked credentials line by line. Skips binary content and files over 1 MB, so results stay fast and focused.

--severity--max-findings--format human|json
🔐

Named secret detectors

AWS access & secret keys, GitHub PATs, Slack tokens, Stripe live keys, OpenAI keys, private key material, and PostgreSQL/Redis/MySQL/MongoDB connection strings with embedded credentials.

criticalhighmediumlow
∑

Entropy-gated generic detection

Hex and base64 tokens next to credential-looking keys are scored with Shannon entropy plus a length-weighted score — so long, random strings are caught without flagging normal words.

high-entropy-hexhigh-entropy-base64
🚫

Placeholder-aware

Templates tell you where to put a key — that is not a leak. <...>, ellipses, xxxx, changeme, YOUR_KEY_HERE and demo words are never reported.

▤

gitignore-aware traversal

Respects .gitignore, .git/info/exclude, nested .gitignore files and built-in build/vendor dirs. A dedicated .envguard-ignore supports per-file and per-detector suppression.

.envguard-ignoreglob:detector
🩹

Masked findings

The real secret is never printed. Findings display a masked preview like AKIA****ABCD. Secret values stay out of logs, terminals and CI output.

⛓

CI-ready exit codes

0 clean, 1 findings/issues, 2 usage or I/O error. Turn it into a gate in your pipeline and let machines decide, with human-readable output for you.

⌁

Machine-readable JSON

Both commands emit stable JSON (--json / --format json) with paths, line numbers, severities, detector names and masked secrets — ready for sarif or CI parsing.

How it works

From filesystem to a severity-gated decision

  1. Traverse with respect

    Walk the repository, honouring gitignore semantics and .envguard-ignore; skip binaries, oversized and vendored paths.

  2. Apply detectors

    Fourteen regex-and-context detectors run per line: named services first, entropy heuristics for random hex/base64 tokens.

  3. Filter noise

    Placeholder values and suppressed paths/detectors are dropped before anything is reported.

  4. Classify + mask

    Findings get a severity and a masked preview (xxxx****zzzz), then are sorted by path and line.

  5. Emit + exit

    Human or JSON report, plus an exit code your pipeline can enforce. 0 clean, 1 found, 2 error.

Same engine, two surfaces. check compares parsed dotenv key/value entries; scan uses the detection engine above. Both share the placeholder, entropy and masking logic.

Architecture

Small modules, clear boundaries, no imports outside the standard library

cli.py argparse entry→ check.py dotenv lint engine→ output human/JSON→ | scan.py tree traversal→ ignore.py gitignore matcher→ rules.py 14 detectors→ entropy.py Shannon scoring→ output.py findings
ModuleResponsibility
cli.pyargparse surface, path resolution, exit-code contract (0 / 1 / 2).
check.pydotenv parser (quotes, export, comments, duplicates) and example comparison producing CheckIssues.
scan.pyos.walk traversal, binary & size guards, ScanResult with per-severity / per-detector counts.
ignore.pygitignore-style matcher (dir-only, anchored, negations, nested files) plus .envguard-ignore parsing.
rules.pythe 14 built-in detectors with validators, strong-detector guard spans, placeholder recognition and secret masking.
entropy.pyShannon entropy and length-weighted score used to gate generic hex/base64 findings.
output.pyhuman-readable tables and stable JSON serialisation for scans.
Security model

Designed so the scanner itself cannot leak what it finds

🔍

Masking on by default

Findings display at most the first and last four characters (AKIA****ABCD). Output is safe to paste into issues or CI logs.

🧱

Zero-runtime-dependency surface

Only the Python standard library. Fewer dependencies means fewer things to compromise and zero supply-chain surprises at scan time.

⌂

Runs entirely locally

No network calls, no telemetry, no API keys required. Secrets never leave your machine.

⚑

Responsible disclosure

A documented security policy with private advisories and a five-business-day response commitment.

Installation

Verified install — Python 3.9 through 3.13, no dependencies

Source install (verified)

git clone https://github.com/honeyamn10-source/envguard.git
cd envguard
python -m venv .venv && source .venv/bin/activate
pip install -e .
envguard --version

Install from a built distribution

python -m build
pip install dist/envguard-0.1.0-py3-none-any.whl
envguard --version

Requires setuptools & build for the first command. Runtime has no dependencies.

Quick start

Understand it in under a minute

Lint an environment file

# in a project that has .env + .env.example
envguard check .
# treat warnings as errors
envguard check . --strict
# machine-readable
envguard check . --json

Scan for leaked secrets

# scan the current tree
envguard scan .
# only critical findings
envguard scan . --severity critical,high
# stop at the first finding (CI fast-fail)
envguard scan . --max-findings 1 --format json
Exit codes you can gate on: 0 everything clean · 1 findings or lint issues · 2 usage/I/O error.
CI & pre-commit

Gate commits and pipelines

pre-commit hooks (bundled)

The repo ships .pre-commit-hooks.yaml with two hooks:

repos:
  - repo: https://github.com/honeyamn10-source/envguard
    rev: v0.1.0
    hooks:
      - id: envguard-check   # lint .env files
      - id: envguard-scan    # scan the staged tree

CI gate

# GitHub Actions
- run: pip install -e .
  working-directory: ./envguard
- run: envguard scan . --severity critical && envguard check .
  working-directory: ./app

Findings exist → exit 1 → the job fails and the secret is reviewed instead of merged.
