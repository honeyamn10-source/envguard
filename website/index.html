02 / CLI reference

Commands you can trust.

Copy a real command, switch between outputs, and check the exit-code contract before wiring it into CI.

Scan for likely secrets

Pattern and entropy checks produce file-and-line findings with severity filters.

envguard scan . --severity critical,high
envguard scan . --format json
envguard scan . --max-findings 20
⌁ Illustrative finding preview: AKIA****ABCD

Compare .env with .env.example for missing, extra, duplicate and empty required values.

envguard check . --strict
envguard check . --example .env.example
envguard check . --require DATABASE_URL --json
⌁ Use --allow for intentional extra keys.

The CLI returns a stable exit code so automation can branch without parsing text.

0Pass / no findings
1Findings or issues
2Invalid input or runtime error
envguard scan . && echo "clean" || echo "review needed"

05 / Scope & answers

Clear expectations.

Detection is heuristic. Review findings and rotate any exposed credential.

The CLI supports human and JSON scan output; SARIF, JUnit, standalone binaries and Docker images are not supplied here.

Check the latest results in GitHub Actions. A passing automated check covers its tested paths, not every real-world integration.

Does envguard upload files or secrets?

No. The Python CLI scans locally and makes no network calls. Website translation is separate, opt-in, and only sends the public guide text you see below the notice.

How are detected secrets displayed?

Findings use a masked preview such as AKIA****ABCD. The full value is not printed.

What triggers the entropy detectors?

A credential-like key name must appear on the same line, and the token must pass entropy and length gates. Common placeholders are suppressed.

Can I configure envguard with a config file?

No. The implemented interface uses CLI flags such as --severity, --format, --example and --strict.

Which outputs are supported?

Human-readable text and JSON. SARIF, JUnit, binaries and container images are not part of this repository.
